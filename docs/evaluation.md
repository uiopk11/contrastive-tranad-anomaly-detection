# 评估、保存结果与解释边界

## 指标实际含义

`TranAD/src/pot.py::pot_eval` 使用训练分数拟合 POT，随后调用 `adjust_predicts`，利用真实标签将被命中的异常段补齐，再计算 P/R/F1。因此这些 F1 属于 **point-adjust（PA）后指标**，不是未经调整的严格点级检测性能，也不是独立的事件级 Precision/Recall。

`calc_point2point` 的 `ROC/AUC` 输入是调整后的二值预测，而非连续异常分数。不能把它与从连续分数计算的 ROC-AUC 或 AP 直接比较。部分 notebook 的后续绘图另算连续分数曲线，二者含义不同。

## 可以追溯的历史观察

在 `results/historical/02_frozen_cl_wadi.json` 中保存的 stdout 包括：

- 基线：PA-F1 0.6383，TP=735、TN=15713、FP=571、FN=262。
- 冻结主干融合，α=0.10：PA-F1 约 0.6640，TP=735、TN=15802、FP=482、FN=262。
- 用同一测试标签搜索 α 后选 α=0.34：PA-F1 约 0.7256，TP=771、TN=15927、FP=357、FN=226。

`03_joint_cl_negative_case.json` 保存的直接联合训练案例为 PA-F1 约 0.1091，TP=997、TN=0、FP=16284、FN=0，表明该阈值下几乎全报异常。不能据此推断所有联合训练都会失败。

`04_frozen_cl_smap.json` 中，P-1 基线 PA-F1 约 0.8915；测试标签选 α=0.06 后约 0.8958。该结果不是整个 SMAP 的平均值。SMD 的 notebook 没有保存可引用指标，不能补写结果。

以上仅是历史文件保存的输出，未通过本次重跑确认；同一 notebook 中修改过的单元与历史输出也可能不对应。原 WADI 增强 notebook 同时存在可选联合训练与冻结分支，且没有完整内核执行轨迹。整理版把两条路径分开，不能反向证明历史主干状态。历史 α 最优值的提升应理解为探索现象。

## 探索 CSV 的已知问题

`results/exploratory/tranad2_cl_eval_summary.csv` 中 Raw 行保存 P≈0.0750、R≈0.7433、F1≈0.1363，但 TN=0、FP=0、FN=73967、TP=98834；这些计数反算得到 P=1、R≈0.5720、F1≈0.7277，与保存指标冲突。PA 行也有冲突。不能用这份 CSV 支撑性能或类别分布结论。

对应 notebook 保存过“Normal support=0”的分类报告，说明标签转换或状态存在问题。整理保留原 CSV 字节并明确标记为探索证据，未伪造修正值。`09` 的 stdout 与对应 CSV 指标也不同，属于不同或状态不明的保存记录，不能组合成同一次实验。

阈值扫描、平滑与段约束网格同样使用测试标签寻找较好指标；它们的最大值不是未见测试性能。

## 后续验证要求

若要评价方法是否稳定有效，应在统一数据处理、相同实体与预算下，分别报告严格点级指标、连续分数 AP/ROC-AUC 和注明标签使用方式的 PA 指标。所有阈值和融合权重应由训练/验证数据决定，再对未用过的测试数据做多随机种子比较。

当前记录不支持全数据集领先、统计显著改进或严格在线检测等更强结论。
